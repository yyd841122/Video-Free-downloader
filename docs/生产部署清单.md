# SaveAny 生产部署清单

本文档面向**正式上线**（HTTPS 域名 + Stripe Live + 真实收款）。本地开发与 Mock 支付请参考 [保姆级本地运行指南.md](./保姆级本地运行指南.md)。

## 一、上线前总览

| 模块 | 本地 Mock | 生产 |
|------|-----------|------|
| 支付 | `MOCK_PAYMENT=true` | `MOCK_PAYMENT=false` + Stripe **Live** 密钥 |
| JWT | 可随意字符串 | **强随机** `JWT_SECRET`（≥32 字符） |
| 前端地址 | `http://localhost:5173` | `https://你的域名` |
| Webhook | `stripe listen` 转发 | Stripe Dashboard 配置 **HTTPS** 端点 |
| 数据库 | SQLite 单文件 | 可继续 SQLite；用户量大建议 PostgreSQL |
| 下载目录 | `backend/downloads/` | 需足够磁盘 + 定期清理（已内置 worker） |

## 二、环境变量（`backend/.env`）

复制 `backend/.env.example` 为 `backend/.env`，生产环境至少确认：

### 必改项

```env
MOCK_PAYMENT=false
JWT_SECRET=<用 openssl rand -hex 32 生成>
FRONTEND_URL=https://你的域名
ALLOWED_ORIGINS=https://你的域名
DEEPSEEK_API_KEY=sk-xxx

STRIPE_SECRET_KEY=sk_live_xxx
STRIPE_WEBHOOK_SECRET=whsec_xxx
STRIPE_PAYMENT_METHODS=card,alipay,wechat_pay

# 建议在 Stripe Dashboard 为每个套餐创建 Price，并填入 price_ 开头的 ID
STRIPE_PRICE_MONTHLY=price_xxx
STRIPE_PRICE_QUARTERLY=price_xxx
STRIPE_PRICE_YEARLY=price_xxx
STRIPE_PRICE_LIFETIME=price_xxx
```

### 建议检查项

| 变量 | 说明 |
|------|------|
| `VIP_FILE_RETENTION_SECONDS` | 会员任务目录保留秒数，默认 3 天（259200） |
| `FREE_FILE_RETENTION_SECONDS` | 免费用户约 6 小时（21600） |
| `VIP_CONCURRENT_DOWNLOAD` | 会员并发下载数，默认 3 |
| `MAX_DOWNLOAD_BYTES` | 单任务最大体积，默认 2GB |
| `ASR_ENABLED` | 无字幕转写；生产需自建 Whisper 服务并填 `ASR_BASE_URL` |

运行自检：

```bash
cd backend
python scripts/check_production.py
```

## 三、Stripe Live 配置步骤

### 1. 切换 Live 模式

在 [Stripe Dashboard](https://dashboard.stripe.com) 右上角关闭「测试模式」，使用 **Live** API 密钥（`sk_live_`）。

### 2. 产品与价格

为月/季/年/终身各创建一个 **Product + Price**（币种与 `.env` 中 `BILLING_CURRENCY` 一致，如 CNY），将 `price_` ID 写入对应 `STRIPE_PRICE_*`。

### 3. 支付方式

**Settings → Payment methods** 中开启：Card、Alipay、WeChat Pay（按业务需要）。

### 4. Webhook（关键）

1. **Developers → Webhooks → Add endpoint**
2. URL：`https://你的域名/api/billing/webhook`
3. 事件至少勾选：`checkout.session.completed`
4. 创建后复制 **Signing secret**（`whsec_`）→ `STRIPE_WEBHOOK_SECRET`

> 支付成功开通会员依赖 Webhook；未配置或签名校验失败时，用户付了钱但账号不会变 VIP。

### 5. Checkout 回跳

`FRONTEND_URL` 必须与用户浏览器访问的前端一致（含 `https`），用于：

- `/payment/success?order_no=...`
- `/payment/cancel`

## 四、服务器部署架构（推荐）

```
用户浏览器
    │
    ▼
Nginx（443，HTTPS）
    ├── /          → frontend/dist 静态文件
    └── /api/      → reverse_proxy → uvicorn 127.0.0.1:8000
```

前端构建后使用**同源** `/api` 请求（无需改 `client.js`），由 Nginx 转发到后端。

### 后端启动（示例）

```bash
cd backend
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# 配置好 .env 后：
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

> 下载任务状态在进程内存中；多 worker 会导致任务查询不一致，**生产建议 `--workers 1`**，或后续改为 Redis 任务存储。

### 前端构建

```bash
cd frontend
npm ci
npm run build
# 将 dist/ 部署到 Nginx root
```

### Nginx 片段示例

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    root /var/www/saveany/frontend/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 3600s;
        client_max_body_size 32m;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## 六、安全与运维建议

1. **不要**将 `backend/.env` 提交到 Git。
2. 生产关闭或限制 Swagger：`uvicorn` 前加防火墙，或改 `main.py` 仅在 `DEBUG` 时挂载 docs。
3. `JWT_SECRET` 泄露等于全员可被伪造登录，务必轮换并重启。
4. 监控 `backend/downloads` 磁盘占用；会员多、批量多时考虑缩短 `VIP_FILE_RETENTION_SECONDS`。
5. 定期备份 `backend/data/app.db`（SQLite）。
6. DeepSeek / ASR 按量计费，关注 `FREE_AI_SUMMARY_PER_DAY` / `VIP_AI_SUMMARY_PER_DAY`。

## 七、常见问题

### 付了钱但不是会员

- 查 Stripe Webhook 是否 4xx/5xx
- 确认 `STRIPE_WEBHOOK_SECRET` 与 Dashboard 一致
- 确认 endpoint 为 `https://域名/api/billing/webhook`（不是 `/api/payment/webhook`）

### 批量下载提示「最多 3 个任务」

- 正常：前一批未完成会占满并发槽
- 等任务完成或重启后端（会清空内存任务表，**会中断进行中的下载**）

### 任务进度接口 500

- 已修复：`eta` 字段为整数；若仍报错请拉最新代码并重启后端
