# SaveAny 变现路径评估与支付方案决策

> **产品：** SaveAny 万能视频下载器（视频解析下载 + AI 总结 MVP）  
> **阶段：** Beta（Soft Launch 已通过）  
> **文档版本：** 2026-05-25  
> **相关文档：** [post-soft-launch-roadmap.md](./post-soft-launch-roadmap.md) · [payment-live-mode-dry-run-plan.md](./payment-live-mode-dry-run-plan.md) · [stripe-test-mode-validation-report.md](./stripe-test-mode-validation-report.md)

**声明：** 本文档为内部决策参考，不构成法律、税务或合规意见。具体签约、费率、风控以各平台最新政策为准。文中 **不记录** 任何 API Key、商户号或密钥。

---

## 决策背景摘要

| 现状 | 含义 |
|------|------|
| Stripe **Test Mode** 已跑通 | Checkout → Webhook → VIP 发放技术闭环可用 |
| Stripe **Live** 对个人主体可能不可行 | 需商户资质、业务说明；视频下载类风控较严 |
| **暂不正式收费** | Beta 继续 Test Mode + 明确「非正式扣款」 |
| 已有 **VIP + 订单系统** | 后续无论哪条支付路线，可复用会员时长与权限模型 |
| **ASR 未开放** | 定价叙事以「下载 + AI 总结（字幕）」为主，避免过度承诺 |

**产品类型：** 数字工具 / SaaS / 会员订阅（非实体、非课程平台为主）。

**合规提醒（全路径共通）：** SaveAny 涉及第三方平台视频解析下载，任何收款方（MoR、支付机构）都可能询问 **版权、合理使用、用户协议、退款政策**。上线正式收费前须确保 Terms / Privacy / 版权说明已就绪（当前已上线基础版）。

## 1. 当前保留 Stripe Test Mode

| 项 | 说明 |
|----|------|
| **定位** | 技术验证与 Beta 内测，**不是真实变现主路径** |
| **用途** | 验证 Checkout、Webhook、订单状态、VIP 发放、resume/cancel、与 Account 展示 |
| **对用户** | 须持续标明 **Test Mode / 内测支付验证 / 非正式扣款**（见 Soft Launch 文案） |
| **对团队** | 保留现有 `MOCK_PAYMENT=false` + Test 密钥配置，作为后续切换 MoR / Live 的参考实现 |
| **退出条件** | 选定正式收款方案并完成合规评审后，再讨论是否下线 Test 或仅保留 staging |

**结论：** 继续保留，**不** 对外宣传为「已开通正式收款」。

## 2. 国际 Merchant of Record（MoR）路线

MoR 平台作为 **名义卖家**，代处理全球税务、发票、部分合规，开发者集成 Checkout 或 API 后分成入账。

### 2.1 候选平台概览

| 平台 | 适合 SaaS/数字产品 | 税务处理 | 中国开发者友好度 | 风控/审核 | 接入难度 | SaveAny 合规关切 |
|------|-------------------|----------|------------------|-----------|----------|------------------|
| **Paddle** | ⭐⭐⭐⭐⭐ 经典 SaaS MoR | 强（VAT 等） | 中等（需 KYC，部分地区受限） | 中高；软件/SaaS 成熟 | 中 | 需说明产品非盗版工具；下载器类可能需补充 FAQ |
| **Lemon Squeezy** | ⭐⭐⭐⭐ 数字产品/SaaS | 强 | 中等 | 中；对 indie 友好 | 低–中 | 类似 Paddle，强调用户自担版权 |
| **Creem** | ⭐⭐⭐⭐ 面向 SaaS/AI 工具 | 有 MoR 能力（以官网为准） | 相对友好（华人社区讨论较多） | 中 | 低–中 | 与现有 Stripe Test 验收文档已衔接，可优先调研 |
| **Dodo Payments** | ⭐⭐⭐ 新兴 MoR | 宣称 MoR | 待核实 | 中–高（新平台） | 低–中 | 需验证视频/下载类是否允许 |
| **FastSpring** | ⭐⭐⭐⭐ 企业向数字商务 | 强 | 中等 | 高（审核严） | 中高 | 更适合成熟产品；Beta 期可能过重 |
| **Cleverbridge** | ⭐⭐⭐ 软件许可/订阅 | 强 | 中等 | 高 | 高 | 偏企业软件销售流，SaveAny 体量可能不匹配 |

### 2.2 综合分析

**优势**

- 无需自建全球税务与部分发票逻辑。
- 通常支持信用卡 + 部分地区本地支付。
- 与 SaveAny 现有「订阅时长 / 一次性套餐」模型较契合（映射为 Product/Price）。

**风险**

- **业务类型审核：** 「视频下载 / 多平台解析」可能被归类为高风险或灰色，需在申请时如实描述为 **个人学习备份、已有版权内容**，并引用 Terms。
- **中国开发者收款：** 多数 MoR 支持 PayPal/银行/Wise 等到账，但 **大陆个人无海外公司** 时，提现、外汇、税务申报仍需自行处理。
- **与 Stripe 关系：** Creem 等可能与 Stripe 生态有交集；避免 Test/Live 密钥混用。

**推荐动作（Beta 期）**

1. 并行 **书面调研** Creem、Lemon Squeezy、Paddle（各填申请表或联系销售，问清「video downloader SaaS」是否接受）。
2. 用 **最小 SKU**（如月付）做 sandbox 联调，**不** 对国内用户大规模开放。
3. 保留现有订单表结构，新增 `payment_provider` 字段列为 **P1 技术项**（本轮不改代码）。

## 3. PayPal 路线

| 维度 | 评估 |
|------|------|
| **定位** | 短期 **人工收款** 或 **MoR 提现通道**，不宜作为长期主订阅引擎 |
| **优势** | 用户认知度高；个人/小微可申请；可作为「第一笔钱」验证付费意愿 |
| **劣势** | 订阅能力弱于 Stripe；争议与 **冻结** 风险；对数字服务风控敏感 |
| **SaveAny** | 可用于：用户 PayPal 付款 → 管理员核对邮箱 → **手动开通 VIP**（见第 5、8 节） |
| **提现** | 大陆账户提现路径、手续费、年度额度需单独规划 |

**结论：** **辅助路线**，配合人工开通 VIP，**不** 替代 MoR 或官方国内支付。

## 4. 国内官方支付路线

### 4.1 候选

| 方式 | 说明 |
|------|------|
| **支付宝电脑网站支付** | PC 浏览器跳转支付宝；适合桌面用户 |
| **支付宝手机网站 / APP 支付** | 移动端 H5 / 唤起支付宝 |
| **微信支付商户号** | JSAPI / H5 / Native；国内用户习惯好 |

### 4.2 分析

| 维度 | 说明 |
|------|------|
| **主体** | 通常需 **个体工商户** 或 **公司**；纯个人无法官方商户号（政策以支付宝/微信最新为准） |
| **材料** | 营业执照、对公账户或法人结算、经营类目选择；网站 **ICP 备案** 常被要求 |
| **适合度** | **国内用户付费转化率** 最优路径之一 |
| **接入成本** | 中–高（签约、密钥、回调、对账、退款接口） |
| **合规** | 经营类目需与「软件服务 / 信息技术」匹配；视频下载工具可能需补充说明 |
| **与 SaveAny** | 长期若主要用户在国内，**值得** 在 3–6 个月规划个体户 + 双通道 |

**结论：** **长期主路径候选**，短期 Beta **不** 强推（主体与备案周期长）。

## 5. 人工收款路线

| 项 | 说明 |
|----|------|
| **方式** | 微信/支付宝 **个人收款码**、PayPal 个人链接；用户付款备注 **注册邮箱** |
| **履约** | 管理员在后台或数据库 **手动延长 VIP**（需配套工具，见第 10 节） |
| **适合** | 第一笔付费验证、10–20 人 Beta、无商户号阶段 |
| **不适合** | 规模化、自动续费、发票、对账、争议处理 |
| **风险** | 个人收款限额与风控；税务合规；用户纠纷无平台仲裁 |
| **文档** | 须在 Beta 邀请中写明：**非自动开通、24h 内处理、备注邮箱** |

**结论：** **短期 0–1 个月推荐** 与 Test Mode 并行，作为 **唯一可能产生真实收入** 的低风险试验。

## 6. 平台型变现

| 平台 | 类型 | 与 SaveAny 关系 | 账号体系 |
|------|------|-----------------|----------|
| **爱发电** | 赞助/月付 | 适合「支持开发者」叙事 | 需人工核对赞助者邮箱 → VIP |
| **知识星球** | 社群会员 | 教程 + 下载技巧 + 内测群 | 与 App VIP 分离或捆绑高价套餐 |
| **小报童** | 专栏/付费内容 | SEO 与教程导流 | 弱关联 |
| **Gumroad** | 数字商品 | 可卖「使用指南」非主订阅 | 弱关联 |
| **Patreon / Ko-fi** | 海外赞助 | 海外用户 | 人工关联邮箱 |

**分析**

- **优势：** 无需自建支付合规；快速验证「是否有人愿意付钱」。
- **劣势：** 与 SaveAny **VIP 权限脱钩**，运营成本高；难以支撑 1080p / AI 配额自动化。
- **定位：** **品牌与社区**，非核心 SaaS 计费引擎。

**结论：** 可作为 **辅助曝光与赞助**，主订阅仍应走 MoR 或国内官方支付。

## 7. 广告与联盟

| 类型 | 说明 |
|------|------|
| **Google AdSense** | 需内容站流量与合规；下载工具站审核可能敏感 |
| **广告联盟（百度/字节等）** | 需备案与一定 PV |
| **AI 工具 / 云服务联盟** | 推广 API、存储、转码服务；与产品相关 |
| **SEO 内容页** | 教程、平台对比、长尾词；长期获客 |

| 维度 | 评估 |
|------|------|
| **依赖** | 流量；Beta 阶段 PV 不足，**收入极低** |
| **优势** | 不依赖支付商户号；与 Test Mode 无冲突 |
| **风险** | 广告与「无广告付费会员」叙事冲突；体验下降 |

**结论：** **长期辅助收入**，优先级低于订阅与人工收款验证。

## 8. 推荐阶段路线

### 短期（0–1 个月）— Beta 验证付费意愿

| 动作 | 说明 |
|------|------|
| ✅ 保留 Stripe Test Mode | 仅技术验证，文案标明非正式扣款 |
| ✅ 开通 **人工收款 SOP** | 微信/支付宝/PayPal + 备注邮箱 + 手动 VIP |
| 🔲 设计 **后台手动开通 VIP** | 下一技术任务（见第 10 节） |
| 🔲 并行申请/邮件咨询 **Creem、Lemon Squeezy、Paddle** | 问清业务类型是否接受 |
| ❌ 不对国内用户宣布正式收费 | |

### 中期（1–3 个月）— 单一正式支付上线

| 动作 | 说明 |
|------|------|
| 确认 **1 个 MoR**（或 Stripe Live + 海外主体） | 签约、sandbox、生产 Webhook |
| 接入正式 Checkout | 复用现有订单与 VIP 模型 |
| 上线 **管理端手动开通/延期/退款备注** | 兜底人工收款与纠纷 |
| 完善退款 SLA 与客服流程 | support@cozyguidehub.com |
| 小范围 **真实收费** Beta（如 20–50 人） | 监控 P0 与争议率 |

### 长期（3–6 个月）— 双轨与成本定价

| 动作 | 说明 |
|------|------|
| 国内 **个体户/公司** + 支付宝/微信 | 服务国内主用户 |
| 或 **海外主体 + Stripe Live / MoR** | 服务海外用户 |
| **ASR 计费策略** | 外部 API 按量 + 会员次数包 |
| 评估广告/联盟 | 有稳定 SEO 流量后再开 |
