# 全能视频下载网站 MVP 开发方案

## 1. 目标

开发一个轻量、前后端分离的视频下载网站，支持用户从多个平台解析视频信息，并通过两种方式下载：

- 服务端下载后提供文件下载链接
- 解析真实媒体直链后提供重定向或代理下载

项目定位为学习与个人合法备份工具。默认不提供绕过 DRM、付费墙、平台权限限制的能力，并在页面中展示版权与账号风险提示。

## 2. 技术栈

- 前端：Vue 3 + Vite
- 后端：FastAPI
- 下载核心：yt-dlp
- 数据存储：MVP 阶段无数据库，使用内存任务状态和本地下载目录
- 文件目录：后端下载文件统一存放在 `backend/downloads`

## 3. MVP 范围

首版实现：

- 单链接视频信息解析
- 服务端下载任务创建
- 下载进度轮询
- 下载完成后提供文件链接
- 直链解析
- 直链重定向
- 直链代理下载
- 移动端适配
- 页面展示版权、风控、账号风险提示

暂不实现：

- 登录注册
- 付费能力
- 数据库
- 历史任务持久化
- AI 总结
- 字幕翻译
- 大规模批量队列

## 4. 下载模式

### 4.1 服务端下载模式

流程：

```text
用户提交链接
-> 后端创建任务
-> yt-dlp 下载到 backend/downloads
-> progress hook 更新任务状态
-> 下载完成后返回 /api/files/{task_id}
```

优点：

- 成功率更高
- 支持合并音视频
- 适合移动端保存
- 适合后续字幕、AI 总结等处理

缺点：

- 占用服务器磁盘和带宽

### 4.2 直链重定向/代理模式

流程：

```text
用户提交链接
-> yt-dlp extract_info(download=False)
-> 按用户选择匹配 format
-> 返回 direct_url、redirect_url、proxy_url
```

优点：

- 服务器压力小
- 速度可能更快

缺点：

- 部分平台直链有效期短
- 部分直链依赖 headers、cookies 或 referer
- 对需要合并音视频的平台不一定可用

## 5. 后端接口

### GET /api/health

健康检查。

### POST /api/video/info

解析视频信息，不下载。

请求：

```json
{
  "url": "https://example.com/video"
}
```

响应包含标题、封面、作者、时长、格式列表等。

### POST /api/video/download

创建服务端下载任务。

请求：

```json
{
  "url": "https://example.com/video",
  "format": "best",
  "with_subtitle": false
}
```

响应：

```json
{
  "task_id": "uuid",
  "status": "queued"
}
```

### GET /api/tasks/{task_id}

查询任务进度。

### GET /api/files/{task_id}

下载服务端已完成文件。

### POST /api/video/direct

解析直链，返回真实链接、重定向链接和代理链接。

### GET /api/redirect/{token}

跳转到解析出的真实媒体链接。

### GET /api/proxy/{token}

通过后端代理真实媒体链接，尽量保留 yt-dlp 解析出的请求头。

## 6. 前端体验

参考 `https://ai.codefather.cn/painting` 的轻商业风格：

- 白底
- 顶部轻导航
- 蓝色主按钮
- 圆角输入区
- 卡片网格承载卖点和结果
- 文案突出效率、高清、移动端、批量能力

首屏是“下载控制台”，不是传统营销落地页：

- 大输入框
- 模式切换：服务端下载 / 直链模式
- 清晰度选择：最佳 / 1080p / 720p / 仅音频
- 字幕尝试开关
- 主按钮：开始解析

## 7. 风险与限制

- 不承诺支持所有平台
- 不绕过 DRM 和付费限制
- 默认不保存 cookies
- 直链有效期可能较短
- 服务端文件需要定期清理
- 线上部署必须限制并发、文件大小、任务时长

## 8. 验收标准

- 后端服务可启动
- 前端服务可启动
- 首页在桌面和手机宽度可用
- 能解析有效视频链接
- 服务端下载任务能显示进度
- 下载完成后能保存文件
- 直链模式能返回重定向/代理入口
- 错误链接有明确提示
- 页面包含合规和风险提示
