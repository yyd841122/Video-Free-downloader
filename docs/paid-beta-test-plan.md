# SaveAny 小额人工付费 Beta 测试计划

> **产品：** SaveAny 万能视频下载器  
> **线上：** https://videodown.cozyguidehub.com  
> **阶段：** Beta — 小额人工付费验证（非 Stripe Live、非网站自动扣款）  
> **文档版本：** 2026-05-28  
> **相关文档：** [manual-payment-vip-grant-sop.md](./manual-payment-vip-grant-sop.md) · [monetization-paths.md](./monetization-paths.md) · [beta-feedback-log.md](./beta-feedback-log.md)

**声明：** 本文档为内部测试与运营模板。文中 **不记录** 完整用户邮箱、收款码、API 密钥或付款截图。

## 1. 测试目标

本轮 **不是** 大规模收费或公开售卖，而是用小样本验证：

| 验证项 | 说明 |
|--------|------|
| 付费意愿 | 是否有人愿意为 SaveAny 付「第一笔钱」 |
| 流程理解 | 用户是否理解 **人工付款 → 手动开通**（非网站自动扣款） |
| 开通顺畅度 | 管理员按 SOP 执行 CLI，VIP 是否在 Account 正确展示 |
| 权益预期 | 高清、批量、AI 总结等会员能力是否符合用户预期 |
| 留存意向 | 付费后是否愿意继续使用、是否愿意推荐 |
| 价值排序 | 用户最看重：**下载** / **高清** / **批量** / **AI 总结** 中的哪一项 |

**当前路径：** 用户线下付款 → 管理员 SSH 执行 `admin_grant_vip.py` → 用户刷新 `/account` 查看会员。

**明确不是：**

- Stripe Live 正式收款  
- 网站 Checkout 自动扣款（前台 Stripe 仍为 Test Mode，勿误导为「已开通正式支付」）

## 2. 测试范围

| 建议 | 说明 |
|------|------|
| 人数 | 先 **1–3** 位熟人或半熟人 |
| 套餐 | 每人仅 **monthly（月度）** |
| 暂不推 | **lifetime**、公开售卖、长期服务承诺 |
| 能力边界 | **不承诺** ASR 自动转文字；**不承诺** 所有平台 100% 可下 |
| 沟通 | 私聊/小群为主，不做大规模投放 |

扩大至 5–10 人的条件见 [第 10 节](#10-成功判断标准)。

## 3. 推荐价格

| 类型 | 金额 | CLI `amount_cents_reported` | 说明 |
|------|------|----------------------------|------|
| 标准测试价 | ¥19 / 月 | `1900` | 与当前套餐标价一致 |
| 优惠测试价（可选） | ¥9.9 / 月 | `990` | 仅用于极小规模验证，需在记录表备注 |

- 订单表 `amount_cents` 仍为套餐标价（如 ¥19）；实收以 `amount_cents_reported` + 记录表为准。

## 5. 用户付款前说明（必发要点）

发给用户前，建议确认对方已读以下要点：

1. **网站支付：** 站内 Stripe 仍为 **Test Mode**，本次 **不是** 在网站上自动扣款。  
2. **本次 Beta：** **人工付款** + 管理员 **手动开通 VIP**。  
3. **付款后需提供：** 在 SaveAny **注册的邮箱**（与登录 Account 一致）。  
4. **开通后自查：** 打开 https://videodown.cozyguidehub.com/account ，查看会员有效期与 **MAN** 开头订单（已支付）。  
5. **ASR：** 当前 **未开放** 无字幕自动转文字；AI 总结需视频字幕或自行上传 SRT/VTT。  
6. **平台：** 解析/下载受原平台与网络影响，**不保证** 全部链接可用。  
7. **问题反馈：** 优先描述「链接 + 设备 + 现象」，便于复现修复。  
8. **用途：** 个人学习备份，勿用于侵权传播；详见站内用户协议。

## 6. 收款与开通 SOP 摘要

完整步骤见 **[manual-payment-vip-grant-sop.md](./manual-payment-vip-grant-sop.md)**。付费 Beta 流程如下：

| 步骤 | 动作 |
|------|------|
| 1 | 用户 **注册** 并登录 SaveAny |
| 2 | 用户 **提供注册邮箱**（付款备注或私聊） |
| 3 | 用户 **付款**（微信/支付宝/PayPal 等，线下） |
| 4 | 管理员 **确认到账** 与金额 |
| 5 | 服务器 SSH：`admin_grant_vip.py` **dry-run** 预览 |
| 6 | 核对无误后加 **`--confirm`** 开通 |
| 7 | 通知用户 **刷新 /account** |
| 8 | 填入本文 [第 8 节](#8-付费用户记录表) 记录表 |

## 7. CLI 命令模板

在服务器 `backend` 目录执行。将 `user@example.com`、`manual-YYYYMMDD-user-monthly-001` 替换为实际值。

### dry-run（不写库）

```bash
python scripts/admin_grant_vip.py \
  --email user@example.com \
  --plan monthly \
  --reason "wechat payment" \
  --admin-email support@cozyguidehub.com \
  --amount-cents-reported 1900 \
  --request-id manual-20260528-user-monthly-001
```

### confirm（真实开通）

```bash
python scripts/admin_grant_vip.py \
  --email user@example.com \
  --plan monthly \
  --reason "wechat payment" \
  --admin-email support@cozyguidehub.com \
  --amount-cents-reported 1900 \
  --request-id manual-20260528-user-monthly-001 \
  --confirm
```

**`reason` 参考：** `wechat payment` | `alipay payment` | `paypal payment` | `beta gift` | `support compensation`

## 10. 成功判断标准

### 可以继续扩大测试（目标 5–10 人）

需 **同时满足** 或大部分满足：

- [ ] 1–3 人中，至少有人 **真实付款** 或 **明确表示愿意付费**  
- [ ] 手动开通流程 **无操作错误**（dry-run → confirm 一次成功）  
- [ ] 用户 **理解** 人工付款与能力限制（未大规模误解为「网站已正式收款」）  
- [ ] 至少 **1 人** 完成一次有效 **下载** 或 **AI 总结**  
- [ ] 无未解决的 **P0** 问题  

### 不应扩大测试

出现以下任一情况，**暂停拉新**，先修产品或流程：

- 用户普遍 **不理解** 人工付款流程  
- VIP 开通 **频繁出错** 或 Account 状态不一致  
- **下载主流程** 对付费用户大面积失败  
- 出现 **支付/会员权益争议**（开错人、重复开通未解释清楚）

## 11. 后续决策

根据 1–3 人测试结果，归入三类之一：

### 情况 A：有人愿意付费

**继续：**

- 扩大到 **5–10** 人，仍优先 monthly  
- 打磨 [manual-payment-vip-grant-sop.md](./manual-payment-vip-grant-sop.md) 与记录表  
- 调研 **MoR / Creem / Paddle / Lemon Squeezy**（见 [monetization-paths.md](./monetization-paths.md)）  
- 评估 **Admin API** 或简易后台页，减少 SSH 依赖  

### 情况 B：无人付费，但愿意免费用

**继续：**

- 优化核心价值（下载成功率、总结质量、 onboarding）  
- SEO / 教程内容引流  
- 调整定价叙事或会员权益组合后再做第二轮付费试探  

### 情况 C：无人愿意用

**回到：**

- 需求验证：是否场景不够痛、竞品已满足、触达人群不对  
- 重新访谈，寻找更高频、更愿付费的细分场景
