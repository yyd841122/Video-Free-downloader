## 1. Beta 测试目标

本轮 Beta（B1）在 Soft Launch 已通过的基础上，将测试规模从 **3–5 人扩大到 10–20 人**，重点收集真实使用数据而非功能开发。

| 目标 | 说明 |
|------|------|
| 扩大测试人数 | 10–20 名志愿者，受控邀请，非公开大规模推广 |
| 收集真实视频链接 | 用于 [platform-compatibility-samples.md](./platform-compatibility-samples.md) 样本库 |
| 收集失败案例 | 解析失败、下载失败、AI 总结失败、支付 / 权限异常 |
| 验证手机端体验 | 封面、布局、粘贴链接、下载与 AI 流程 |
| 验证用户理解度 | 是否理解 Stripe Test Mode（非正式扣款）、AI 需字幕/上传、ASR 未开放 |
| 验证错误提示 | 失败时是否清楚「下一步该做什么」 |

反馈渠道：`support@cozyguidehub.com` 或本表（由协调人录入）。

## 2. 反馈等级定义

### P0 — 阻断级（立即处理，暂停扩大测试）

- 页面打不开 / 白屏
- 无法注册 / 登录（主流浏览器）
- 无法解析 **主流平台** 代表性链接（B 站 / 抖音 / X）
- 无法下载（720p 主链路）
- 会员权限异常（已付费无 VIP、免费误开通 VIP）
- Stripe Test Mode 支付流程断裂（Checkout / Webhook / VIP 未到账）
- 后端 500 / 服务长时间不可用
- 数据错乱 / 安全风险（串号、泄露他人数据）

### P1 — 严重体验（本轮回修优先）

- 提示不清楚或误导（尤其支付、AI、会员）
- 手机端布局 / 交互问题
- 某些平台兼容性差但非全失败
- AI 总结流程困惑（不知要上传字幕、按钮无反馈）
- Account / 任务记录不友好（失败原因不明）
- 文案与真实能力不一致
- 失败后不知道下一步操作

### P2 — 优化与规划（记录 backlog）

- 新功能建议
- ASR 自动转文字
- 更多平台支持
- SEO / 公开推广
- 正式收费（Stripe Live / 其他）
- 浏览器插件
- 批量下载增强
- 多语言优化

## 5. Beta 阶段判断标准

### 可以继续 / 扩大测试的条件

- **连续 3 天无 P0**（或 P0 已修复并复验通过）
- **下载主流程成功率可接受**（志愿者主观 ≥4/5，且无集中平台失效）
- **注册 / 登录无阻塞**（含邮箱校验与占位邮箱拦截符合预期）
- **大文件不会压垮服务器**（磁盘保护生效，无因空间导致的批量失败）
- **用户能理解 AI 总结当前限制**（知悉需字幕或上传 SRT/VTT，ASR 未开放）
- **Stripe Test Mode 说明被理解**（未误以为正式扣款）

### 应暂停扩大测试的条件

- 出现 **支付 / 权限 P0**
- **大量解析失败**（同一平台稳定复现）
- **磁盘 / 后端不稳定**（频繁 500、清理失效、服务重启）
- **用户普遍看不懂关键提示**（同一困惑点 ≥3 人反馈）
- 单日 **P0 ≥ 1** 且未修复

### 与路线图衔接

- 满足扩大条件 → 进入 [post-soft-launch-roadmap.md](./post-soft-launch-roadmap.md) Phase B2 体验优化
- 样本积累充分 → 更新 [platform-compatibility-samples.md](./platform-compatibility-samples.md) 回归清单
